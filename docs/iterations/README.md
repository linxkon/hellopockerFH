# 迭代策略与实验记录

这里存放每一次具体迭代的方案、执行证据和评估结论。一轮一个文件；[AGENTS.md](../../AGENTS.md) 负责稳定的项目认知，本目录负责可检验、可修正的具体研究记录。

策略收益评估采用 [六人桌评估方案](../six_player_evaluation.md)：候选与 2～3 个历史强版本的独立实例同桌，并与固定基线进行配对比较。每轮在记录中落实对手名单、版本冻结、配比、种子和采纳条件。

## 使用方式

1. 从下方索引选择与任务相关的记录，核对其数据环境、版本和适用范围，无需每次通读全部历史。
2. 复制 [TEMPLATE.md](TEMPLATE.md)，命名为 `YYYY-MM-DD-NN-short-topic.md`。日期使用 Asia/Shanghai，`NN` 为当天顺序号，例如 `2026-10-09-01-decision-trace.md`（仅为命名示例）。
3. 开始时填写方向、问题证据、假设、执行计划和评估标准，并加入索引；执行期间更新同一文件。
4. 收尾时补全实际改动、测试方法与结果、结论和下一步，同步索引。新的独立假设或下一轮升级另建文件并链接前序记录。

记录要形成可接续的链条：**前轮证据 → 本轮问题与假设 → 执行 → 测试评估 → 结论 → 下一轮待验证问题**。若本轮结果推翻原假设，保留原计划并说明修正原因，不把计划改写成事后必然成功的叙述。

## 记录约定

- 状态使用：`计划中`、`执行中`、`待评估`、`已结束`、`受阻`。结论单独填写：`未定`、`采纳`、`继续验证`、`放弃`；应用状态单独说明未应用、仅本地应用、已线上应用或已回退。
- “已结束”表示本轮已有明确收尾结论，不表示实验有效或已经上线。只做分析、发现无效、样本不足或中途受阻，也要如实留下结果。
- 实现前确定主要指标、比较方法和采纳条件；结果出来后若调整指标，说明原因，并区分探索性发现与独立验证。
- 记录可重跑的命令、代码与配置版本、种子、座位安排、对手组合、数据范围和结果路径。存在未提交修改时，单独写 Git commit 不足以复现，还需相关源码哈希或保存的补丁/快照位置。
- 线上、进程内回测、local_arena 选手与管理员数据分别标记。区分行为正确性、策略收益和运行成本；缺失数据、未运行测试或不适用项目明确填写原因。
- 私有牌谱、数据库、凭证及大量原始输出仍留在仓库外。本目录保存必要的脱敏摘要和证据定位信息；外部文件可能无法在其他机器访问，需说明环境及重建方式，不复制密钥或聊天。
- 保留失败实验与适用范围；后续推翻旧结论时，在旧记录追加更正和新记录链接。历史建议是待验证线索，不是后续 Agent 必须执行的方向。
- 按任务范围与资源安排实验，运行和上线遵循根目录约定。记录下一步不代表自动启动下一轮或自动替换线上策略。
